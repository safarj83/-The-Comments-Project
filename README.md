Домашнее задание №6: Лоадеры и улучшение работы с промисами
Что было сделано:

Рефакторинг асинхронного кода (Цепочки промисов):

Полностью убраны вложенные then во всех частях приложения. В events.js цепочка выстроена линейно: addCommentAPI().then(() => loadComments()).then(() => renderComments()).catch().finally().

В main.js используется loadComments().then().catch().finally().

Добавление состояния загрузки при старте приложения:

В index.html добавлен блок <div id="loadingComments"> с текстом «Загрузка комментариев...».

В main.js этот блок отображается при запуске (style.display = 'block') и скрывается в блоке .finally() после получения данных или ошибки.

Добавление состояния загрузки при добавлении комментария:

При нажатии на кнопку «Написать» в events.js форма добавления (addFormContainer) скрывается.

Вместо нее показывается надпись «Комментарий добавляется...» (addingComment).

По завершении запроса (в .finally()) форма возвращается на место, а надпись скрывается, что предотвращает случайную повторную отправку комментария.

Исправление ошибки 400 (Bad Request):

Из функции addComment в api.js удален заголовок Content-Type: application/json, который вызывал CORS-preflight ошибку на стороне сервера и приводил к коду 400.

Исправление валидации после успешного добавления:

Из блока .finally() в events.js убран вызов validateFields(). Это позволило избежать появления ложных сообщений об ошибках после того, как поля успешно очищались.

Корректное форматирование дат:

В main.js данные теперь загружаются через функцию loadComments() из data.js, которая использует formatDate() из utils.js. Это гарантирует, что все комментарии (и старые с сервера, и новые) отображаются в едином формате ДД.ММ.ГГ ЧЧ:ММ.

Архитектура и структура кода:

Вся логика получения данных вынесена в отдельную модульную функцию loadComments() в data.js.

Модули api.js, data.js, events.js, render.js, utils.js четко разделены по зонам ответственности.

Домашнее задание №7: Обработка ошибок API и валидация
В рамках данного этапа был полностью переработан пользовательский сценарий при ошибках. Приложение теперь не просто блокирует кнопку, а использует системные уведомления alert и корректно обрабатывает сбои на всех уровнях.

Какие ключевые вопросы были решены:

Изменена логика валидации полей (короче 3 символов):

Отказались от блокировки кнопки и статичного текста ошибки под полями.

Кнопка «Написать» теперь всегда активна. При попытке отправить данные короче 3 символов выводится alert с текстом: «Имя и комментарий должны быть не короче 3 символов».

Главное: Введенные данные не сбрасываются и остаются в форме, чтобы пользователь мог их исправить.

Обработка ошибок сервера (код 400 и 500):

Добавлена обработка 400 Bad Request от API (например, когда имя или текст не проходят серверную валидацию). Ошибка выводится через alert.

Добавлена обработка 500 Server Error. Теперь при любом сбое на стороне сервера (в GET или POST запросах) пользователь видит alert с текстом: «Сервер сломался, попробуй позже».

Обработка отсутствия интернета (Network Error):

Перехвачена ошибка TypeError: Failed to fetch в блоке .catch() для всех запросов.

Пользователю выводится alert с текстом: «Кажется, у вас сломался интернет, попробуйте позже».

Сохранение данных при ошибке (Anti-loss UX):

Логика очистки формы (nameInput.value = '', textInput.value = '') вынесена строго в блок .then() успешного ответа.

В блоках .catch() и .finally() поля не очищаются, что полностью исключает потерю текста пользователем при сетевых сбоях или ошибках сервера.

Тестирование сбоев через forceError: true:

Для возможности продемонстрировать наставнику обработку ошибки 500 в POST-запрос временно добавлен параметр forceError: true, который заставляет сервер в половине случаев возвращать ошибку 500.

Чистая архитектура ошибок:

Вся логика формирования сообщений об ошибках теперь сосредоточена в api.js. Модуль events.js только выводит их через alert, что делает код более чистым и удобным для поддержки.
